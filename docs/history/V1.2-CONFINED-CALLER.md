# Production confined caller — v1.2

The untrusted builder and candidate run under distinct AppContainer package SIDs,
restricted LOW tokens and zero capabilities. The trusted operator/broker holds
enrollment, review, measurement and final Git promotion authority. The native
launcher measures the suspended child token before resuming it, supplies an
explicit non-secret environment, inherits no handles and waits for job cessation.

This boundary protects against the confined caller, not an attacker already
holding the normal user's unrestricted token or administrator authority.
No separate service account, machine-wide firewall or elevation is claimed.
The separate-account install plan remains unverified on this host.

## Actual production path

The npm distribution includes the native runtime and six measurement programs
on an exact packaging allowlist. Asset paths are bound to the installed package
at build time, never selected through caller environment variables. Measurement
hashes the installed bundle and these assets, not an unrelated checkout.
`node tooling/probes/v12-packed-provider-audit.mjs` installs the local tarball
outside the checkout and runs the production authority/custody battery through it.
The single-executable LOCAL distribution does not provision this Node/npm-backed
provider; use the npm distribution or checkout for Windows HARDENED enrollment.

Operator commands are `provider enroll <base> <new-store>`,
`provider serve-production <store>` (also `provider serve` for an enrolled store),
and `provider launch <store> <temp-work> <program> [args...]`.

The native named-pipe broker measures the client's kernel token. A matching
confined caller sends a file-map proposal, not a command or a destination.
Request text is encoded as a JSON string in both the trusted controller envelope
and journal; it cannot inject or overwrite the broker's observed client fields.
The production measurement requires an executed framing-injection denial, with
an unsafe-framing control that reproduces the outer-field replacement.
The trusted controller imports the proposal into its private Git worktree,
uses the existing candidate verification, requirement and discrimination gates
under a separate confined verifier, then issues an Ed25519 receipt bound to the
deployment, project, candidate, proposal digest, exact commits and nonce.
Promotion consumes that receipt, re-verifies, applies in the broker and checks
the resulting head, tree and clean readback. Reservation never authorizes caller
apply. Direct writes to the base, key, enrollment, anchor and held checkout are
denied by the OS boundary.

The initial enrollment refuses executable/extended Git configurations,
submodules and linked tracked files. Trusted Git uses disabled hooks, fsmonitor,
global/system configuration and signing. After candidate execution, changed
Git metadata and introduced linked paths fail closed before further trusted Git.
Only the private readonly Node/npm runtime is granted to the verifier.
Unsupported commands or infrastructure do not become passing verification.

## Measurement custody and activation

`provider measurement-begin <store>` invalidates old evidence and starts a new
challenge. `provider measure-production <store>` requires the matching production
review/promotion/attack transcript, executes native attacks against this store
and both of its actual package SIDs, and publishes schema
`amabie-production-measurement/2`.

The private Ed25519 key stays in deployment custody. The public key, generation
and current-record hash are anchored outside caller-selected stores, under the
current SID's OS-registered profile (not an environment-selected home).
The record binds the current host/SID, canonical store, enrollment, deployment,
tool/runtime bytes and challenge. Raw native return codes, token measurements,
authority exchanges, pipe descriptor and independent listener observations are
validated; aggregate PASS/available booleans are not authority.

Freshness is at most 15 minutes from measurement start. Reading valid saved
evidence also requires a live signed broker response to a fresh random challenge,
bound to that deployment, generation and exact measurement. Missing, dead,
wrong-key, wrong-generation, wrong-deployment or replaying brokers cannot activate.
Any missing or inconclusive required observation makes all six controls unavailable.
Schema 1 is permanently retired and cannot activate, even when re-signed.

## Executable coverage

`node tooling/probes/v12-production-authority.mjs` and the default
`v12-confined-caller.mjs` run the same production-linked battery. They are
alternative entry points, not independent evidence to sum.

Native attempts run in both caller and verifier packages: inherited file handle,
inherited process-handle duplication, acquiring/duplicating a broker handle,
direct/extended/relative/dot/junction/actual-file-symlink reads, copy, rename,
five authority-write targets and descendant reads. Each has an unrestricted
successful control. Environment separation is checked additionally and is not
inflated into the native syscall count.

Egress uses a controlled listener on the host's local IPv4 address, separate
trusted connection journal, unrestricted successful connection before and after
the attack, and the Windows network-isolation diagnostic or WSAEACCES.
A timeout or absent connection alone never passes. This measures controlled TCP,
not an exhaustive UDP/IPv6/all-endpoint policy.

The positive pipe is the actual production transport. The negative pipe omits
the package allow grant, retains the owner grant and records its descriptor:
unrestricted connects; confined execution receives access denied. Medium
integrity alone, or a deny ACE alone, is not credited as this denial mechanism.
The production pipe's LOW mandatory label is installed and read back natively.

`node tooling/probes/v12-hardened-activation.mjs` runs the activation unit suite
using a live deployment built by that production probe. Negative raw records are
deliberately re-signed by the trusted test operator to test validation independently
of signatures. No fabricated positive record is used.

The old standalone blob harness remains available with
`v12-confined-caller.mjs --legacy` for historical diagnostics only. Its retired
activation and loopback-timeout results are not release evidence.
