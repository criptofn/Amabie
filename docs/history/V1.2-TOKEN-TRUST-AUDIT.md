## Trust findings

**Self-binding: CONFIRMED.** Raw traces show the worker editing package proof
declarations, committing/stashing them and rerunning setup. Regression-guard
also attempted new proof scripts. This is not merely speculation from prose.

The model-free `v12-local-self-binding-audit.mjs` independently reproduces it:
six requirements initially refuse; the same unrestricted identity inserts six
bindings, commits, calls setup, and the previously refused work opens.
This is an executed **successful attack**, not a passing security test.

Authority owner: the Windows user launching both setup and the benchmark's
Claude process. `run-trial.mjs` grants shell and filesystem tools without the
native confined caller. Setup can issue a new local seal using that user's
store. A signature authenticates the local key, not a separate human operator.
Blocking only `bind`, setting a worker environment variable, or changing the
prompt cannot repair this: the worker can edit declarations and invoke setup
directly, and shares access to the authority store and program installation.

The existing production broker uses a distinct restricted AppContainer caller
and broker-owned verification/promotion. The local attack does **not** establish
an escape from that native boundary. However, the benchmark does not launch its
model worker through that boundary. A networked model CLI cannot simply be
dropped into a zero-egress, secret-free caller and expected to retain API access.
The integration needs trusted model transport separated from confined tools or
data-only implementation proposals. That integration remains unimplemented.

## Containment implemented — not the completed trust repair

The workflow harness now calls the actual `work` gate deterministically before
any model process. Unbound tasks terminate there. Other preflight failures also
stop. A successful preflight still refuses with
`CONFINED_WORKER_INTEGRATION_UNAVAILABLE`: no fall-through to the unrestricted
worker and no insecure opt-out. This intentionally makes the workflow arm
unavailable until the missing integration is implemented and tested.

Refusals use a separate `amabie-benchmark-preflight/1` schema, with null delivered
correctness and explicit worker calls/tokens/turns. No synthetic oracle or agent
result is generated. Existing output records cannot be overwritten by a retry.
No fixture, hidden oracle, proof binding, native boundary, or product gate was
modified. Local setup itself is **not repaired** by this harness containment.
